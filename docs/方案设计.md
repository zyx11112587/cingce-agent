# 考公 RAG 问答系统方案设计

## 1. 目标

系统统一处理行测 Markdown 真题、政治理论 PDF、申论 Markdown/DOCX/PDF 和其他综合资料，提供真题检索、考点问答、解析查询和材料归纳。

## 2. 用户场景

| 场景 | 输入 | 输出 |
|---|---|---|
| 行测真题检索 | 关键词、题干、年份、科目 | 原题、选项、答案、解析、图片、来源 |
| 政治理论问答 | 概念、政策、原文片段 | 结论、理论依据、资料出处、页码 |
| 申论材料归纳 | 材料主题、题干、作答要求 | 材料观点、提炼结果、适用结构、来源 |
| 解析查询 | qid、题干、近似题干 | 候选题、标准答案、官方解析、相关考点 |

## 3. 总体架构

```text
Markdown / PDF / DOCX / TXT
            |
      文档解析与分页
            |
Question / Chunk / Image / Page
            |
   SQLite FTS5 BM25  +  Embedding
            |                 |
            +------ RRF ------+
                     |
               Top-K 证据
                     |
       LLM API 生成 / 本地原文回退
                     |
           Web UI / HTTP API / CLI
```

## 4. 设计原则

1. 行测真题按单题保存，PDF/DOCX 按页码和段落保存。
2. 关键词检索和向量检索解耦，向量未配置时保留 BM25。
3. PDF、DOCX、Markdown 和 TXT 使用统一 Chunk 模型。
4. 检索结果必须包含来源、页码和检索路径。
5. 申论回答区分材料原文和模型提炼，禁止混淆。
6. 扫描版 PDF 明确提示 OCR 缺失，不静默丢弃。

## 5. 验收标准

- 可以同时导入 `xingcezhenti`、政治理论 PDF、申论材料。
- BM25 和向量双路召回可用，结果按 RRF 融合。
- 配置 embeddings API 后能生成向量索引。
- 未配置 embeddings 时仍能查询行测真题和新资料。
- API 返回 `retrieval_mode`、BM25 排名、向量排名和来源页码。
