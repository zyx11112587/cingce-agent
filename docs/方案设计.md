# 考公 RAG 问答系统方案设计

## 1. 目标

系统面向考公真题和解析资料，提供真题检索、考点问答和解析查询。目标是把 Markdown 与图片资料转化为可追溯的结构化知识，并在本地环境中提供可运行的检索和问答服务。

## 2. 用户场景

| 场景 | 输入 | 输出 |
|---|---|---|
| 真题检索 | 关键词、题干片段、年份、科目 | 原题、选项、答案、解析、来源、图片 |
| 考点问答 | 自然语言问题 | 结论、证据、例题引用、来源、置信度 |
| 解析查询 | 题干、qid、近似题干 | 候选题、标准答案、官方解析、相关考点 |

## 3. 总体流程

```text
Markdown + 图片
      ↓
Front Matter、题目、选项、答案、解析、图片解析
      ↓
Question / Chunk / Image 结构化数据
      ↓
SQLite FTS5 trigram 索引
      ↓
查询意图、元数据过滤、证据召回
      ↓
OpenAI 兼容 API 生成，或本地证据摘录回退
      ↓
Web UI / HTTP API / CLI
```

## 4. 核心设计原则

1. 真题以单题为最小单元，不把一道题拆成不可还原的片段。
2. 图片与题目通过 `qid` 和 `image_id` 建立稳定关系。
3. 检索和生成解耦，未配置模型时仍可使用检索与解析功能。
4. 默认使用本地 SQLite，不依赖云数据库和外部向量服务。
5. API 回答必须带来源，证据不足时明确拒答。

## 5. 验收标准

- 能正确解析当前仓库的 `qid`、选项、答案和官方解析格式。
- 关键词和题干片段可以召回原题。
- 解析查询可以返回标准答案和解析。
- 图片引用可以通过本地 API 打开。
- 配置 OpenAI 兼容接口后可以通过 API 生成带来源答案。
- 未配置接口时系统仍可运行。
