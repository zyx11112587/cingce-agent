# 考公 RAG 技术方案

## 1. 技术栈

| 层 | 实现 |
|---|---|
| 语言 | Python 3.11+ |
| 解析 | 标准库 `re`、`html`、`pathlib` |
| 存储 | SQLite |
| 检索 | SQLite FTS5 trigram + bm25 |
| 服务 | 标准库 `http.server` |
| 前端 | 原生 HTML/CSS/JavaScript |
| 生成 | OpenAI 兼容 `chat/completions` API，可选 |

默认不要求第三方包。这样可以先用标准库完成本地运行，后续再接入向量模型、OCR 或本地大模型。

## 2. 数据结构

| 表 | 作用 |
|---|---|
| questions | 保存题目、选项、答案、解析和来源 |
| chunks | 保存题目块、解析块和知识点块 |
| search_fts | FTS5 trigram 全文检索索引 |
| images | 保存图片路径、题目关系和图片标识 |

`Question` 和 `Chunk` 都保留 `source_rel`，用于在回答中显示原始 Markdown 来源。

## 3. 解析规则

解析器兼容当前题库的格式：

```text
## 第 1 题　<sub>qid 2262734 · 图形推理</sub>
- **A**. 选项文本
**答案**：C
**官方解析**
```

同时支持：

- YAML Front Matter 中的试卷、地区、年份、模块。
- Markdown 图片 `![alt](path)`。
- HTML 图片 `<img src="...">`。
- HTML 标签和 `<br>`。
- `../90-图片/...` 相对图片路径。

## 4. 检索策略

1. 识别查询中的 `qid`，优先做精确题号查询。
2. 使用 FTS5 trigram 对题干、选项、答案和解析做全文召回。
3. 通过 year、subject、region、question_type 做元数据过滤。
4. 按 `search`、`knowledge`、`explain` 对题目块和解析块进行分值调整。
5. 对短查询或特殊字符查询使用文本包含回退。

## 5. API 生成链路

```text
用户问题
  → 检索证据
  → 上下文组装
  → OpenAI 兼容 chat/completions
  → 带来源回答
  → API 不可用时原文摘录回退
```

环境变量：

```text
EXAM_RAG_LLM_BASE_URL=http://127.0.0.1:11434/v1
EXAM_RAG_LLM_API_KEY=
EXAM_RAG_LLM_MODEL=qwen2.5:7b
```

## 6. 运行方式

```powershell
python -m exam_rag.cli ingest --input xingcezhenti
python -m exam_rag.cli serve
```

Windows 也可以使用：

```powershell
.\run.ps1 ingest
.\run.ps1 serve
```

## 7. 后续增强

- 接入重排模型，提高考点问答的 Top-K 质量。

- 增加索引版本、增量导入和导入报告。
- 增加 Evaluate 集，评估 Recall@K、引用覆盖率和答案忠实度。
